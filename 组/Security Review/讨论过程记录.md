## 一、讨论演进脉络

### 阶段 1：综述分析——建立问题全景

**输入：** *Safety in Embodied AI: A Survey of Risks, Attacks, and Defenses*（2026，400+ 引文）

**做了什么：** 逐层深入分析五层攻击面，识别出具身AI最具特色的攻击方向。

**五层攻击面：**

| 层 | 内容 | 产出文件 |
|------|------|------|
| §2 感知层 | 视觉/听觉/空间/运动/跨模态融合 | [Safe in EAI---总结/EAIAttack_Perception.md](Safe%20in%20EAI---总结/EAIAttack_Perception.md) |
| §3 认知层 | 指令理解/世界模型/推理 | [Safe in EAI---总结/EAIAttack_Cognition.md](Safe%20in%20EAI---总结/EAIAttack_Cognition.md) |
| §4 规划层 | 任务规划/轨迹规划/多智能体 | [Safe in EAI---总结/EAIAttack_Planning.md](Safe%20in%20EAI---总结/EAIAttack_Planning.md) |
| §5 执行交互层 | 控制/人机交互/多智能体协同 | [Safe in EAI---总结/EAIAttack_Action.md](Safe%20in%20EAI---总结/EAIAttack_Action.md) |
| §6 Agentic 层 | 工具使用/记忆/自我进化/级联风险 | [Safe in EAI---总结/EAIAttack_Agentic.md](Safe%20in%20EAI---总结/EAIAttack_Agentic.md) |

**关键产出：**
- **语义-物理鸿沟**：BADROBOT 三种越狱攻击路径（Contextual Jailbreak / Safety Misalignment / Conceptual Deception）
- **跨模态融合的反直觉脆弱性**：融合不是冗余保护，融合机制本身就是攻击面——单通道即可攻陷整体融合
- **Grounding Failure**：推理逻辑自洽但物理不可行

**过程中的重要讨论：**
- NeRF/3DGS 攻击 vs 世界模型攻击的区别：一个篡改「AI 看到的静态地图」（感知），一个篡改「AI 理解的物理规律」（认知）
- 每个攻击方向标注了「🔥等级」，区分传统攻击与具身独有攻击

### 阶段 4：研究问题提炼——从大问题到可操作问题

**起点：**「具身指令的物理上下文安全校验」——太大，需要三次收窄。

#### 第一次收窄——限定威胁类型

- **放弃：** 防御传感器攻击（独立问题，安全四大有大量研究）
- **聚焦：** 防御 **LLM 规划器被越狱**后输出「语义正确但物理危险」的指令

**攻击场景示例：**
> 被越狱的 LLM 输出「以最短路径到达目标」→ 经过湿滑厨房斜坡 → 负重 5kg → 摩擦力不足 → 摔倒
> LLM 文本层面完全合理，物理层面致命

#### 第二次收窄——限定物理维度

- **不做：** 所有物理上下文
- **聚焦：** **地面稳定性**（摩擦系数、倾斜角、承重能力）
- **选择理由：**
  - 传感器数据获取最直接（IMU + 力传感器 + 深度相机）
  - 物理规律最清楚（摩擦公式 + 重心稳定性）
  - 安全阈值最容易量化

**世界模型方向被否定：**
- 世界模型正确性验证是开放理论难题
- 我们的问题可用显式物理公式解决，不需要神经网络学物理

#### 第三次收窄——限定场景与任务

- **场景：** 家用移动操作机器人
- **任务：**「把 X 搬到 Y」类搬运任务（排除复杂接触式操控）
- **理由：** 移动搬运的物理安全性最可量化评估

**收窄后的研究问题：**
> 当机器人收到搬运类自然语言指令时，如何确保即使 LLM planner 被越狱，物理安全校验仍然可靠执行？

**产出：** [具身安全方向.md](Safe%20in%20EAI---总结/具身安全方向.md)

### 阶段 5：为什么是具身独有——威胁模型论证

**核心论证链条（三段论）：**

```
1. 传统机器人中规划器是可信的
   （A*/RRT/MPC——数学确定、不会被"说服"）
   → 安全校验的定位是辅助性冗余（防数值误差）
   → 软件层校验即可

2. 具身AI 中 LLM 规划器不可信
   （可被语义越狱，BADROBOT 证明三种攻击路径）
   → 攻击者用自然语言"说服" LLM 输出危险指令
   → 这在传统机器人中不存在（无自然语言接口，无法"说服"规划器）
   → 这在纯 LLM 中后果不同（文本 ≠ 物理伤害）

3. 因为规划器不可信，安全校验的定位变了
   → 从"辅助冗余"变成"最后防线"
   → 从"软件即可"变成"必须硬件隔离"
   （同 OS 的校验可被越狱的 LLM 绕过）
```

**结论：** 这是具身AI独有的安全威胁——「LLM 的语义越狱面 × 物理执行的后果严重性」。传统机器人安全和 LLM 安全都不覆盖这个问题。

---

### 阶段 6：TEE 定位的讨论与校准

**关键讨论——「TEE 是不是核心贡献」：**

用户提出质疑：TEE 是现成工具，我们不能改它，核心贡献应该是安全校验本身怎么做，TEE 只是锦上添花。

**讨论结论：**

| 层次 | 内容 | 定位 |
|------|------|------|
| 语义-物理交叉安全校验方法 | 如何从传感器数据提取物理参数、如何将指令语义映射到物理约束、如何设计安全判据 | **核心贡献（科学问题）** |
| TEE 隔离部署 | 保证校验逻辑不被攻陷的 OS 绕过 | **架构增强（工程贡献）** |

- TEE 是**拿来用的**（类比「我们用 Linux」），不是拿来改的
- 汇报时明确：80% 讲安全校验思路，20% 提 TEE 作为防御纵深

**TEE 的传统用途 vs 我们的新用途：**

| | 传统用途 | 我们的新用途 |
|------|------|------|
| 保护对象 | 数据机密性（指纹不出安全区、密钥不泄露） | 物理安全判据的正确执行（判据不被绕过、不被篡改） |
| 典型场景 | 移动支付、DRM、身份认证 | 具身AI物理安全最后防线 |

### 阶段 7：方案架构讨论

**三件事为什么不能全丢进 TEE：**
- TEE 资源极度受限（1-32MB 内存，无 Python/PyTorch/驱动）
- 设计目标就是「最少代码 = 最小攻击面」
- 软件侧做资源密集的事情（传感器处理），TEE 只跑几十行安全判据

**软件侧为什么用规则而非 AI：**
- 「不能让 LLM 审查 LLM 的输出」——越狱的 LLM 不能自己审核自己
- 指令解析用简单规则（模板匹配/正则），物理判据用显式公式（摩擦力方程）

**为什么篡改传感器数据只会让判据更严格：**
- 攻击者篡改物理参数 → 只会让参数看起来更危险 → 判据更严格地拦截
- Attack surface 的单向性——安全设计上的好性质

---

### 阶段 8：可行性与路线

**纯软件学生能不能做 TEE：能。**
- OP-TEE + QEMU 是纯软件仿真环境，一条命令启动
- 写的是 C 代码，不需要硬件知识
- 安全判据代码不超过 500 行

**推进路线：**

```
仿真阶段（2-3 月）           TEE 阶段（2 月）            真机阶段（后期）
┌─────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│ Gazebo 仿真      │    │ QEMU + OP-TEE    │    │ PuppyPi 树莓派    │
│ 物理上下文提取    │ →  │ 判据迁移到       │ →  │ TrustZone 部署    │
│ 安全判据验证      │    │ Secure World     │    │                  │
└─────────────────┘    └──────────────────┘    └──────────────────┘
```

## 二、研究定位总结

### 三方空白的交汇点

```
        AI 顶会                    安全四大
    （有问题意识，              （有技术深度，
     无安全机制深度）            无具身AI视角）
          \                       /
           \                     /
            ┌───────────────────┐
            │    我们的研究空间   │
            │  TEE 嫁接具身安全   │
            └───────────────────┘
                    │
            现有具身安全
        （纯物理层或纯语义层，
         不做交叉校验）
```

### 一句话总结

**将安全四大中成熟的 TEE 机制嫁接到具身AI的物理安全校验上**——不需要设计新芯片，利用现有 TEE 技术做架构创新，解决具身AI独有的、现有两个社区都不覆盖的安全问题。

### 核心贡献公式

```
具身AI独有安全威胁 = LLM 语义越狱面 × 物理执行后果严重性
```
