> **规划者：** 高级规划 Agent（负责拆解任务 + 编写提示词）
> **执行者：** 研究 Agent（负责具体文献调研与信息提取）
> **把关者：** 用户（负责审核方向、验收产出）
> **日期：** 2026-06-18

## 〇、背景与困境

### 当前状态

经过前期调研（综述分析 + AI 顶会扫描 + 安全四大调研），我们初步将方向收窄为「具身指令的物理上下文安全校验——TEE 隔离部署」。但在组会汇报后，导师指出两个核心问题：

1. **问题定义不清晰**：感觉像是自己创造了一个攻击场景，然后自己想办法去解决。问题来源缺乏文献支撑，显得"拍脑袋"。
2. **方法与问题脱节**：TEE 的结合显得强行——根本原因还是问题没定义清楚，所以方法无从谈起。

### 关键约束

- **问题必须有迹可循**：必须是学术界已经有人指出过、讨论过的问题，不能是自己发明的。
- **必须有具身AI特色**：不能是传统模型攻防（对抗样本、经典越狱）的简单迁移。
- **硬件/芯片关联是加分项**：但不强求在问题定义阶段出现，先定问题再想方法。
- **当前阶段只定义问题**：不讨论方法、不讨论实现。

### 核心策略转变

```
之前的错误思路：           正确的思路：
我们发明一个问题          社区已经识别了问题 X
    ↓                        ↓
我们提出方法解决它         现有方法无法解决 X（因为 Y）
    ↓                        ↓
（感觉像自说自话）         我们需要新方法（硬件可能自然成为答案）
```

**关键原则：问题必须来自文献，我们只是发现者/定义者，不是发明者。**

## 已有调研素材（你可以引用和扩展）

### 素材 A：综述 Safety in Embodied AI (2026, 400+ refs)
该综述识别了具身AI的五层攻击面（感知→认知→规划→执行→Agentic），
并提出了 7 个开放挑战。以下是我们已经提取的关键攻击方向：

1. **语义-物理鸿沟（BADROBOT）**：LLM 安全训练在文本空间完成，
   执行在物理空间，两者间的语义鸿沟是可利用的攻击面。
   BADROBOT 识别了三种攻击路径：Contextual Jailbreak / 
   Safety Misalignment / Conceptual Deception。
   
2. **Grounding Failure（接地失效）**：LLM/VLM 推理逻辑自洽但
   物理上不可执行——面对不可行指令不做拒绝，而是"将就"替代方案。
   例如：火灾中导航到"服务器机房"而非紧急出口
   （因为推理出机房有灭火系统="安全"）。

3. **跨模态融合的反直觉脆弱性**：单通道 200 个对抗点可攻陷整个
   camera+LiDAR 融合系统（99% 成功率）；时序错位（DejaVu）
   导致 3D 检测崩溃 88.5%。融合不是冗余保护，融合机制本身是攻击面。

4. **记忆投毒（AgentPoison）**：Agent memory 独立于模型参数，
   投毒一条记忆永久有效，跨 session 持续触发不安全行为。

5. **自我进化的安全悖论**：四条退化路径——参数漂移/记忆累积/
   工具腐败/工作流退化。Agent-SafetyBench：无一 agent 通过 
   60% 安全评估。

6. **Agent 技能市场供应链**：31,000+ agent 技能中 26% 含安全漏洞。

7. **自然语言=双向社会工程攻击面（PsySafe）**：Agent 通过多轮
   对话建立信任→心理操控用户；用户通过自然语言注入有害倾向。

### 素材 B：综述的 7 个开放挑战（§7）
尤其是 #4 "安全感知的具身硬件设计"——传感器/执行器的硬件漏洞
无法仅靠软件防御弥补，需要软硬件协同安全设计。

### 素材 C：AI 顶会 23 篇安全论文

### 素材 D：安全四大 ~1,500 篇论文

| **`academic-paper`** | 后续论文写作（当前阶段不需要） | Phase 3 完成后 |

### 建议执行流程

```
/deep-research → 产出候选问题池（子任务 1）
     ↓
用户审核 → 筛选 Top 3 候选
     ↓
研究 Agent 执行子任务 2（深度追踪 Top 3）
     ↓
用户审核 → 选定最终问题
     ↓
/academic-paper-reviewer → 模拟导师视角挑毛病（可选但推荐）
     ↓
研究 Agent 执行子任务 3（问题定义撰写）
     ↓
用户最终验收
```

## 五、验收标准

### Phase 1 验收标准
- [ ] 候选池包含 8-12 个问题
- [ ] 每个候选有 ≥2 篇独立文献支撑
- [ ] 每个候选有明确的"具身独特性"论证
- [ ] 用户能从候选池中明确选出 Top 3

### Phase 2 验收标准
- [ ] 每个 Top 3 候选有完整的引用链溯源
- [ ] 防御覆盖度矩阵清晰展示了研究空白
- [ ] 具身特色度评分 ≥12/20（否则放弃该候选）
- [ ] 用户能明确选定最终问题

### Phase 3 验收标准
- [ ] 问题能一句话概括
- [ ] 威胁模型无模糊地带
- [ ] 与现有工作的区分精确到"读者不会混淆"
- [ ] 导师看完后能说"这个问题确实存在且重要"
