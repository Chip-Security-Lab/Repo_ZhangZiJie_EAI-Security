## 背景：研究方向的演进

经过两轮调研（Phase 1 候选池 + Phase 1.5 deep-research 独立调研）和一轮深度追踪（Phase 2 八篇论文），我们将研究方向收敛为：

> **LLM 规划器在具身场景中产生 grounding failure——它生成计划时隐含地假设了某些物理前提成立（如「地面能走」「摩擦力足够」），但这些前提在真实物理环境中可能不成立。当前所有防御（ConceptAgent、DDCG、VerifyLLM、SAFER、ILION）都在语义/逻辑/几何层做验证，没有一个从传感器数据提取真实物理参数来检验 LLM 的物理前提是否成立。**
>
> **我们定义的问题是：如何设计一个独立于 LLM 规划器的物理前提验证机制——从传感器数据提取物理参数，检测 LLM 计划中隐含的物理前提是否在当前环境中成立。**

**当前阶段：只定义问题，不讨论方法（不提 TEE，不设计架构）。**

## Part B：问题展开（论文 Introduction 级别）

写 4 段文字：

### 段 1：具身AI 的新风险

LLM 作为机器人规划器带来了传统机器人没有的攻击面。引用：
- BADROBOT（ICLR 2025）：语义-物理鸿沟，三种越狱攻击路径
- Blindfold（SenSys 2026）：动作级越狱，93.2% ASR，绕过所有现有防御
- Causal-Plan-Bench（2026）：VLM 是「表面 token 预测器」而非物理因果推理器

### 段 2：社区已经识别了这个问题

Grounding failure 已被多篇独立论文记录。引用：
- Chakraborty et al.（幻觉率 ↑40%）
- Han et al.（火灾→服务器机房经典案例）
- Causal-Plan-Bench（1,200 实例系统诊断，SOTA 模型仅得 45.28/100）
- EMNLP 2025 Findings（12 模型系统研究）

### 段 3：现有防御为什么不够

已有防御分为三条路线，各有盲区：

| 路线 | 代表工作 | 局限 |
|------|---------|------|
| 优化 LLM 规划 | ConceptAgent（前置条件验证）、DDCG（NeurIPS 2025 Workshop，可行性/质量判据分离）、Causal Reasoner（因果推理训练） | ConceptAgent 的前置条件由 LLM 自己生成（「LLM 审查 LLM」），限于 17 个布尔谓词，不涉及连续物理量。DDCG 的 C_F 从 VirtualHome 文本数据学习，不接入传感器。所有方案都被 Blindfold 绕过 |
| 形式化/几何验证 | VerifyLLM（IROS 2025，LTL 验证）、SAFER（IROS 2025，多 LLM+CBF）、ILION（确定性几何验证） | LTL 和嵌入空间几何无法表达连续物理约束（摩擦力、倾角、负重的具体数值）。SAFER 的 Safety LLM 本身也是 LLM——同样可被越狱 |
| 传统物理安全 | CBF/MPC 约束（SAFER 的控制层） | 仅覆盖运动学约束（避障、关节限制），不覆盖物理前提（地面摩擦是否足够支撑负重搬运） |

**三条路线的共同盲区：没有一个从传感器数据提取真实物理参数来验证 LLM 的物理前提。**

### 段 4：我们需要什么

不是「验证指令是否物理可执行」（那样会帮攻击者确认恶意指令的可行性）。而是「检测 LLM 的物理理解与传感器观测到的真实物理状态是否一致」——拦截标准是物理前提不成立，而非动作不可行。这需要一个独立于 LLM 规划器的、从传感器驱动的、基于物理公式（非 AI）的验证层。

## Part C：威胁模型

明确列出：

### 系统假设
- 机器人平台：家用移动操作机器人（如带机械臂的移动底座）
- 软件栈：LLM/VLM 作为任务规划器（如 GPT-4o、开源 VLA），将自然语言指令分解为动作序列
- 传感器：IMU、力/力矩传感器、深度相机/RGB-D 相机（可获取地面倾角、摩擦系数估计、负重等物理参数）
- 执行器：机械臂 + 移动底盘

### 攻击者目标
使机器人执行物理上危险的动作——通过越狱 LLM 规划器输出「语义正确但物理前提不成立」的指令。

### 攻击者能力（参考 BADROBOT + Blindfold）
- 通过自然语言/语音与机器人交互
- 可部署本地开源 LLM 作为攻击工具（Blindfold 设定）
- 可在开放环境中预观察场景
- **不能**物理接触机器人、**不能**直接修改机器人软件/硬件、**不能**篡改传感器数据

### 攻击者限制
- 无模型内部访问权（black-box 设定）
- 不能物理篡改传感器（传感器数据在物理层面是真实的）
- 不能绕过硬件隔离的安全校验（如果存在）

### 可信基（TCB）
- 物理传感器数据是真实的（攻击者不能物理接触传感器）
- 物理定律是确定的（摩擦方程、稳定性判据不依赖 AI）

## Part D：问题边界

| In Scope | Out of Scope |
|---------|-------------|
| 检测 LLM 生成的计划中隐含的物理前提是否在真实环境中成立 | 判断指令是否「恶意」（意图检测） |
| 从传感器数据提取物理参数（摩擦系数、倾角、负重） | 防御传感器 spoofing/jamming 攻击 |
| 独立于 LLM 的物理判据（基于物理公式） | 改进 LLM 的物理推理能力 |
| 在物理执行前的安全校验 | 执行中的实时控制安全（CBF/力限制等） |
| 家用搬运类任务（移动 + 抓取 + 搬运） | 接触式精细操控、动态人机协作 |

## Part E：与现有工作的精确区分

为每个相关方向写一句清晰的区分说明（不能模糊）：

- **vs ConceptAgent**：ConceptAgent 用 LLM 生成前置条件（布尔谓词）做验证——验证规范来自 LLM 本身。我们验证规范来自物理公式，不依赖 LLM。
- **vs DDCG**：DDCG 的 C_F 从 VirtualHome 文本数据学习可行性判断——不接入传感器。我们的判据直接从 IMU/力传感器/深度相机读取物理参数，用显式物理方程计算。
- **vs VerifyLLM**：VerifyLLM 用 LTL 形式化规范做逻辑一致性验证——不覆盖连续物理量。我们验证物理前提的连续量值（摩擦力 > 阈值？倾角 < 临界角？）。
- **vs SAFER**：SAFER 用 Safety LLM + CBF——Safety LLM 本身可被越狱。我们的判据不是 AI，无法被语义越狱绕过。
- **vs ILION**：ILION 在嵌入空间做几何验证——几何正确 ≠ 物理安全。我们在物理空间做牛顿力学验证。
- **vs 传统机器人安全（CBF/力限制/急停）**：传统安全覆盖运动学和动力学约束，不覆盖 LLM 特有的语义-物理鸿沟。

---

## Part F：为什么这个问题值得做

1. **如果解决了**：具身AI 在真实部署中多一层不依赖 AI 的物理安全保证。攻击者即使越狱了 LLM，也无法绕过物理定律的校验。
2. **如果一直没人解决**：Blindfold 93.2% ASR 的现实——现有的 LLM 规划器在真实物理环境中是系统性地不安全的，且所有现有防御都在语义层被绕过。
3. **问题的难度**：不是简单的工程问题——难点在于：如何从有限的传感器数据推断 LLM 隐含的物理前提？哪些物理前提是「隐含」的（LLM 没有显式声明的）？如何在物理前提验证和过度保守之间取得平衡？
