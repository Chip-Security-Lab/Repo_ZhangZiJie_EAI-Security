### 1. Blindfold: Jailbreaking Embodied LLMs via Action-level Manipulation

**出处**：Huang et al., SenSys 2026 (ACM/IEEE International Conference on Embedded AI and Sensing Systems)  
**全文获取**：✅ 完整（ar5iv HTML）

**核心方法**

Blindfold 是一个自动化动作级越狱框架，核心创新在于**将攻击域从语义层转移到动作层**。它不尝试让 LLM 说出危险的话，而是让 LLM 规划出表面无害但组合后产生物理伤害的动作序列。

三个关键组件：
1. **命令转换器（Command Transformer）**：攻击者部署一个本地开源 LLM 作为对抗性代理规划器（adversarial proxy LLM）。该代理以恶意意图 + 预观察的环境空间布局 + 通用具身动作池 A 为输入，通过 chain-of-thought 逐步选择最优动作 `a_t(θ_t)`。例如「炸掉用户手机」→ `find(phone) → pick(phone) → move(oven) → stretch()`。
2. **意图混淆器（Intent Obfuscator）**：包含三个子模块——主导动作识别器（dominant action identifier，通过移除每个动作并评估剩余链的危害性变化来定位关键动作）、覆盖动作生成器（cover action generator，将主导动作的参数替换为无害变体，如 `place(phone)` → `place(apple)`）、链融合器（chain fusion，将覆盖分支合并回原始链）。
3. **基于规则的验证器（Rule-Based Verifier）**：用参数化有限状态机编码场景为符号图 `S = (V, E)`，定义每个动作的前置条件函数 `𝒫` 和效果函数 `ℰ`，模拟执行。失败动作触发结构化反馈给代理 LLM，形成规划器-验证器迭代循环直至全部通过。

**实验设置**

| 维度 | 内容 |
|------|------|
| 仿真环境 | VirtualHome（Unity）、Habitat（3D 真实感）、ManiSkill（物理灵巧操作）、RoboTHOR（移动操作） |
| 真实机器人 | UFactory xArm 6（6DoF 机械臂），2 台 RGB-D 相机 |
| 目标 LLM | 开源：Llama-3.1-8B、DeepSeek-R1-14B、Gemma-3-27B、Phi-4-14B（INT8）；闭源：GPT-4o、GPT-4o-mini、GPT-4-turbo、Claude-3.5-sonnet |
| 具身框架 | ProgPrompt、Code-as-Policies、VoxPoser、LLM-Planner |

**关键数据**

| 指标 | 数值 |
|------|------|
| ASR (GPT-4o) | **93.2%** |
| ASR (Phi-4-14B) | **98.1%** |
| 比 SOTA 基线提升 | **+53%** |
| 真实世界（20 指令） | 18/20 绕过防御，12/20 成功执行恶意行为 |
| 移除验证器后 TSR 下降 | GPT-4o: -35.7%, Phi-4-14B: -27.6% |
| 移除混淆器后 ASR 下降 | GPT-4o: -33.4%, Phi-4-14B: -37.1% |

**被测试的防御——全部失败**：

| 防御 | 原理 | ASR 下降 |
|------|------|:--:|
| Llama-Guard | 输入-输出语义过滤 | 7.6% |
| SafeDecoding | 修改 token 预测分布降低有害性 | 4.8% |
| VeriSafe | 形式化验证 LLM 输出是否违反领域安全规则 | 17.9% |

**失败根因**（论文原文）：「语言安全与物理后果之间的根本性不对齐——语义上看起来无害的指令仍然可能导致危险的现实后果。」

**失败案例**
1. **视角不匹配**：攻击者无法获取 agent 的精确空间坐标（如 `move_to(X=1.2,Y=1.4)`），导致 TSR<100%。
2. **混淆器偶尔损害 TSR**：插入的可执行但不直观的覆盖动作使恶意目标失败（GPT-4o TSR 下降 2.3%）。
3. **代理 LLM 幻觉**：生成不符合执行要求的无效输出。
4. **ManiSkill 复杂性**：物理仿真中 agent 控制复杂度更高，TSR 较低。

**安全假设**

| 假设 | 内容 |
|------|------|
| 攻击者能力 | 无盒子访问（无模型内部状态/参数知识）；有限查询预算 |
| 环境预观察 | 目标环境的空间关系短期稳定，攻击者可预观察后离线优化 |
| 本地开源 LLM | 攻击者可部署外部开源 LLM 作为工具 |
| 开放服务环境 | 工厂/商场/公共空间，攻击者可自由发出自然语言指令 |
| 通用动作池 | 具身基元动作可跨异构系统迁移 |

**对我们的意义**（攻击动机）

这是我们防御的**最强动机来源**。Blindfold 证明了三个关键事实：
1. 动作级越狱是真实可行的——93.2% ASR on GPT-4o，真实机械臂验证
2. 所有现有防御（语义过滤、安全解码、形式化验证）均被绕过——因为它们都在语义层操作
3. 防御失败的根本原因是缺乏**物理后果感知**——这正是我们想提供的

**局限/盲区**（从我们视角看）

- 攻击者需要**预观察环境**来构建符号图 S——如果环境动态变化（如有人在房间走动），攻击成功率可能下降。论文承认攻击者可以重新观察并重新发起攻击。
- 规则验证器（有限状态机）的符号图依赖于攻击者手动编码的场景知识——在实际攻击中这需要大量人工。
- Blindfold 的攻击目标是**让 agent 执行恶意动作**——它不覆盖「LLM 真诚但物理上错误地推理」的场景（即 grounding failure 的非恶意变体）。我们的防御目标更广：包括恶意攻击和无意接地失效。
- **论文不提供防御方案**——它纯粹是攻击论文。防御策略仅作为讨论方向提及（多模态对齐、形式化轨迹验证、后果感知防御）。

### 2. Causal-Plan-Bench / Token Predictors Are Not Planners

**出处**：Lu et al. (Tsinghua/MSRA/MBZUAI), arXiv:2606.01810, 2026.06  
**全文获取**：⚠️ 基于摘要 + 补充搜索信息（arXiv 摘要页 + GitHub + HuggingFace + 搜索摘要）。全文 77 页含附录，以下核心细节来自可获取的公开信息。部分标注「待全文确认」。

**核心方法**

核心论断：当前具身 VLM 是「表面 token 预测器」而非「物理因果推理器」——它们利用语言统计先验而非追踪物理因果依赖来生成计划。

三步方法论：
1. **Causal-Plan-Bench**：一个经过多阶段验证的高保真诊断套件，**1,200 实例，12 任务类别**，从四个因果维度评估具身规划。
2. **Causal-Plan-1M**：百万级显式因果推理轨迹语料，通过四阶段标注流水线从自我中心视频中提取。
3. **Causal Planner**：基于 Qwen3-VL-8B 构建，通过渐进式 SFT + RL 训练，使其「内化物理逻辑以实现更精确的下一状态估计」。

**四个因果诊断维度**

| 维度 | 测试内容（基于可获取信息推断） |
|------|------------------------------|
| **Executability（可执行性）** | 验证前置条件——如洗衣前检查口袋、开柜门前确认未锁定 |
| **Effects（效果）** | 确保动作产生预期的状态转换——如确认污渍已被去除 |
| **Composition（组合）** | 结构化因果顺序——如先分类再洗涤，不能颠倒 |
| **Robustness（鲁棒性）** | 意外事件恢复——如捡起掉落的物品、适应环境变化 |

**关键数据**

| 指标 | 数值 |
|------|------|
| Gemini 3 Pro | **38.18** |
| 基线 (Qwen3-VL-8B, 零因果数据) | **33.22** |
| Causal Planner (1M 因果数据) | **45.28** |
| 相对提升 | **36.3%** |
| 因果缩放定律 | 因果训练数据从 0→1M 实例，性能单调提升 36.3% |

**⚠️ 以下细节待全文确认**：各维度的分项得分、12 任务类别的具体列表、Causal-Plan-1M 的四阶段标注流水线细节、训练超参数、跨基准泛化的具体数值。

**安全假设**

论文本身不讨论安全（纯方法论/基准贡献），但其核心论断携带直接的安全含义：
- 当前 VLM 依赖「语言统计先验」而非「物理因果推理」来生成计划 → 意味着它们在训练分布外的物理场景中会系统性地出错
- 因果缩放定律表明，更多的因果推理训练数据可以提升但不是解决这个问题——45.28 仍然远未完美
- Gemini 3 Pro 作为最强大模型之一仅得 38.18，强烈表明这是架构性/范式的局限，而非规模问题

**对我们的意义**（问题存在的证据）

这篇论文直接支撑我们问题定义的**存在性**：
- 「VLM 是表面 token 预测器而非物理因果推理器」= LLM 生成的计划隐含了未经检验的物理前提
- 45.28 的 SOTA 分数（即使经过因果训练）表明这个问题远未解决
- 因果缩放定律表明单纯让 LLM「更好」可能不够——需要外部的、独立的物理验证

**局限/盲区**（从我们视角看）

- 基准测试的是**规划能力**（LLM 能否生成因果正确的计划），而非**验证能力**（能否检测出计划中的因果错误）
- 训练 Causal Planner 是「让 LLM 更好」的路线——这正是我们要差异化的方向
- 基准不涉及安全校验——它不衡量模型能否识别自己的计划在给定物理环境中是否安全
- 四个维度覆盖语义因果（前置条件、效果、顺序、鲁棒性），但**不覆盖连续物理量**（摩擦力、倾角、重量）——这些不在 Causal-Plan-Bench 的评估范围内

### 3. BADROBOT: Jailbreaking Embodied LLM Agents in the Physical World

**出处**：Zhang et al., ICLR 2025  
**全文获取**：✅ 完整（ar5iv HTML）

**核心方法**

BADROBOT 首次系统识别了 LLM 规划器在具身场景中的攻击面。系统 E 建模为四元组 (φ, ψ, ω, S)：语言处理 φ、动作生成 ψ、世界知识 ω、安全约束 S。安全由二元函数 𝒮_L（语言安全）和 𝒮_A（动作安全）评估。

**三种攻击路径的精确定义**：

| # | 攻击路径 | 形式化定义 | 机制 |
|---|---------|-----------|------|
| **J₁** | **Contextual Jailbreak** | (𝒮_L=0) ∧ (𝒮_A=0) | 将 LLM 通用越狱模板（伪装意图、角色扮演、结构化响应、虚拟 AI 仿真、混合策略）适配到具身物理查询——将「说脏话」替换为「用刀刺人」。模型无关（no-box设置）。 |
| **J₂** | **Safety Misalignment** | (𝒮_L=1) ∧ (𝒮_A=0) | LLM 在自然语言中口头拒绝（"抱歉，我不能帮这个忙"），但同时输出 JSON/PDDL/代码格式的危险动作指令（`{'function':[move('use knife to stab human')]}`）。根因：对齐训练数据聚焦安全对话文本，不包括安全结构化输出。 |
| **J₃** | **Conceptual Deception** | (𝒮_L=1) ∧ (𝒮_A=0) with ω→ω' | 世界模型被替换为受损版本 ω'。LLM 拒绝直接指令「毒死那个人」，但接受「把毒药放进那个人嘴里」——语义漂移：指令增量地从善意域滑向恶意域，系统无法识别任务的根本性质已经改变。 |

**威胁模型**

| 维度 | 内容 |
|------|------|
| 攻击者能力 | 弱/无盒子：零先验知识，仅通过语音/文本交互像正常用户一样操作 |
| 攻击者目标 | 主要：强制 AI 执行特定恶意物理动作。次要：获取恶意文本输出 |
| 可信组件 | LLM 本身被假定为已对齐模型。机器人硬件和下游控制模块（运动规划、逆运动学）被信任能忠实执行 LLM 生成的任何动作计划 |
| 不可信组件 | 用户输入通道（语音/文本） |

**关键数据**

- 构造了 230 个恶意物理世界查询（基于 IEEE Ethically Aligned Design + Asimov 三定律，涵盖物理伤害/隐私侵犯/色情/欺诈/非法活动/仇恨行为/破坏七类）+ 100 个来自网络论坛的越狱提示模板
- 在 myCobot 280-Pi 机械臂 + Yi-Large LLM + Yi-Vision VLM 上验证
- **定性案例研究**（无大规模定量 ASR）——论文承认「危害性评估目前较为概念化」
- 最致命的攻击可以「煽动具身 AI 非理性地攻击人类，完全违反阿西莫夫机器人三定律」

**安全假设与防御讨论**

- 论文的安全模型将机器人硬件和控制模块视为可信——它们忠实地执行 LLM 输出。**这恰好是我们想打破的假设**——我们认为控制层之下的安全校验也应该是最后防线。
- 防御讨论在附录中（本次未获取完整内容）。从论文正文推断的隐含防御方向：动作空间对齐训练（为结构化输出而非仅文本生成对齐数据）、因果世界模型（超越 token 概率规划）、多领域专业知识评估。

**对我们的意义**（威胁模型定义）

- BADROBOT 是我们问题定义中**威胁模型的原始出处**
- J₂（Safety Misalignment）和 J₃（Conceptual Deception）精确描述了我们想防御的攻击——LLM 输出了「语义正确但物理危险」的指令
- **关键洞察**：BADROBOT 假设执行层是可信的——动作计划被忠实地转换为物理动作。我们的防御正是在这个假设上插入一个独立的安全校验层
- 我们的定位可以表述为：「BADROBOT 证明了 LLM 规划器不可信；我们提供不依赖 LLM 的独立安全校验，弥补 BADROBOT 威胁模型中缺失的防御层」

**局限/盲区**（从我们视角看）

- 纯攻击论文，无防御方案——我们的防御空间是开放的
- 威胁模型假设「硬件和控制模块是可信的」——在我们的防御架构中，我们假设 OS 可能被攻陷，因此安全校验需要硬件隔离（TEE）
- 攻击成功依赖于手动设计的物理世界查询——Blindfold 在 2026 年实现了自动化（见论文 1），表明攻击面在持续扩大
- 没有讨论 grounding failure 的非恶意变体——LLM 真诚但物理上错误的情况（如「火灾→服务器机房」）不在 BADROBOT 的攻击范围内，但在我们的防御范围内

### 4. ConceptAgent: LLM-Driven Precondition Grounding and Tree Search

**出处**：Rivera et al. (JHU APL/MIT/DEVCOM ARL), arXiv:2410.06108, 2024.10  
**全文获取**：✅ 完整（ar5iv HTML）

**核心方法**

ConceptAgent 是**最接近我们思路的前置工作**——它在 LLM 规划器和物理执行之间插入了一个前置条件验证步骤。但方法细节上有根本性差异。

**三个关键组件**：

1. **谓词接地（Predicate Grounding）**：LLM 收到 JSON 格式的动作名称/描述 + 17 个布尔谓词库（如 `isOpen`、`receptacle`、`pickupable`、`isHoldingObject`）+ 三个逻辑修饰符（`and`、`when`、`exists`），生成每个动作的 PDDL 风格前置条件定义。在执行前，验证函数 `F(s_t, P_c)` 检查当前状态 `s_t` 是否满足动作 `a_c` 的前置条件集 `P_c`——返回 1（全部满足）则执行，返回 0 则拦截并将不满足的前置条件 `U_c` 反馈给 LLM 重新规划。

2. **LLM 引导的 MCTS（LLM-MCTS）**：四阶段——选择（UCB1）、LLM 引导扩展（用 LLM 常识启发式地生成候选动作而非随机枚举）、LLM 评判替代随机 rollout（LLM 对完整计划序列打分 1-10，评估效率/相关性/目标一致性）、反向传播。

3. **动态 3D 场景图**：SAM + CLIP 实例分割和嵌入，投影到 ZED 立体相机的 3D 点云。CLIP 嵌入支持开放词汇检索（如通过余弦相似度区分"cup vs mug"）。

**关键数据**

| 指标 | 数值 |
|------|------|
| 前置条件准确率（precision） | **97.4%**（37/38 正确） |
| 前置条件召回率（recall） | **88.1%**（37/42 ground truth 被捕获） |
| 仿真 Easy 任务（8B LLM） | **18.92%**（vs ReAct 10.26%、ToT 8.11%） |
| 仿真 Moderate/Hard（70B LLM，40 任务） | Full CA: **25%**（vs Baseline 5%、仅 MCTS 5%、仅 PG 12.5%） |
| 真实 Spot 机器人（30 试验） | 40%（低杂乱），20%（未整理前） |
| 步级成功率（乘积效应） | 73% → 100% → 81% → 90% → 68% → 100% → 40%（整体仅 20%） |

**前置条件生成错误**：2.6% 的前置条件是 LLM 幻觉（不正确但被系统采纳）——论文承认这些错误「有真实潜力造成超出基线 agent 的规划伤害」。「6 个缺失的前置条件意味着某些不可行的动作会通过验证门。」

**失败模式**

1. **缺失前置条件**（88.1% 召回）——6/42 ground truth 未被 LLM 生成
2. **状态表示失败**——场景图可能未捕获所有相关状态属性；系统仅限 17 个布尔谓词，无法表达连续量（距离、力、重量）
3. **LLM 幻觉在评判中**——MCTS 评判本身基于 LLM，继承所有幻觉风险
4. **感知级联失败**——每个步骤的感知错误累积，导致整体成功率仅为步级成功率的乘积
5. **杂乱敏感**——高杂乱环境下整体成功率降至 10%

**安全假设**

| # | 假设 | 风险 |
|---|------|------|
| 1 | LLM 生成的前置条件基本正确（97.4% 足够） | 2.6% 误差在安全关键场景中不可接受 |
| 2 | 状态通过场景图完全可观测 | 无传感器噪声/遮挡/陈旧数据处理 |
| 3 | 前置条件是静态且充分的 | 无法从执行失败中学习新前置条件 |
| 4 | 二元门控总是安全的 | 无法处理执行中前置条件被违反的情况（如人进入工作空间） |
| 5 | 物理安全委托给 ROS2 Nav2 | 无碰撞检测/力限制/人存在检测在规划层 |

**对我们的意义**（最关键的差异化对照）

ConceptAgent 是我们的**最直接对照物**。它和我们都做「执行前验证」。但差异是根本性的：

| 维度 | ConceptAgent | 我们的方向 |
|------|-------------|-----------|
| 验证规范的来源 | **LLM 生成**前置条件（同一個 LLM 既规划又定义验证规则） | **物理公式**（摩擦方程、稳定性判据），不依赖 LLM |
| 验证的内容 | 17 个**布尔谓词**（离散/符号化） | **连续物理参数**（摩擦系数、倾角、重量） |
| 状态来源 | 3D 场景图（基于视觉的语义理解） | **传感器数据**（IMU、力传感器、深度相机） |
| 与 LLM 的关系 | LLM 生成验证规范 + LLM 评判计划质量 | **完全独立**于 LLM |
| 验证时机 | 执行前一次性二元门控 | 执行前校验 + 可扩展到执行中监控 |

**局限/盲区**（从我们视角看）

- **「LLM 审查 LLM」架构**：前置条件由 LLM 生成、计划由 LLM 生成、评判也由 LLM 做——虽然在前置条件检查这一步是形式化的（`F(s_t, P_c)`），但验证规范本身来自不可信的 LLM
- **符号化导致物理信息丢失**：任何需要连续量表达的物理约束（如「摩擦力必须 > 0.3 才能安全搬运」）在 17 个布尔谓词系统中无法表示
- **无运行时监控**：验证仅在动作分派时刻做一次。如果动作执行中前置条件被违反（如人进入工作空间），系统无法检测
- **无传感器数据接入**：状态全部来自 3D 场景图（视觉语义理解），不读取 IMU/力传感器/深度信息

### 5. DDCG: Decoupled Dual-Critic Guidance for Embodied Agents

**出处**：Ma et al. (Tianjin University), NeurIPS 2025  
**全文获取**：⚠️ 部分（OpenReview PDF 无法直接解析，基于 NeurIPS 摘要页 + 搜索摘要 + OpenReview 元数据）。标注「待全文确认」的细节需获取全文后验证。

**核心方法**

DDCG 识别了一个被作者称为**「信号混杂（Signal Confounding）」**的关键瓶颈：具身 agent 的反馈信号将**物理不可行的错误**（违反物理/逻辑约束）与**策略上不够优化的选择**（可行的但不最优的）混为一谈——agent 无法区分「我做不到这个动作」和「这个动作不够好」。这种模糊性严重阻碍了有效的计划修正。

DDCG 将反馈解耦为两个独立的判据（critic）：

1. **可行性判据 C_F（Feasibility Critic）**：基于 **RoBERTa** 的二分类器，判断动作在物理/逻辑上是否可执行，定义硬安全边界（安全动作集 A_safe）。落在 A_safe 外的动作概率归零。
2. **质量判据 C_Q（Quality Critic）**：回归模型（基于专家+合成数据训练，评分 3-10），在安全集内评估动作的战略价值。

**CMDP 形式化**：DDCG 被框架化为受约束的优化问题——可行性判据定义硬约束，质量判据在约束内提供奖励梯度。最优策略通过重新加权 LLM 的基础分布得到：
$$\pi^{*}(a|s) = \begin{cases} \frac{1}{Z(s)} \pi^{\text{llm}}(a|s) \exp(r_Q(s,a)/\beta) & \text{if } a \in \mathcal{A}_{\text{safe}}(s) \\ 0 & \text{otherwise} \end{cases}$$

**关键特征**：**不需要更新 LLM 参数**——仅训练轻量级判据模型。

**实验设置与关键数据**（⚠️ 基于搜索摘要，待全文确认具体实验配置）

| 指标 | 数值 |
|------|------|
| 规划器 | GPT-4（作为基础 LLM 规划器） |
| 判据模型 | RoBERTa-base（轻量级，无需更新 LLM） |
| VirtualHome 可执行性 | **95.0%**（vs DGAP 93.3%） |
| VirtualHome 成功率 | **94.1%**（vs DGAP 88.0%） |
| ScienceWorld 总分 | **87.07**，超越所有基线 |
| 特别优势 | 长时域（long-horizon）和泛化（generalization）场景 |

**安全假设**

| 假设 | 风险 |
|------|------|
| C_F 的训练数据覆盖了所有类型的物理不可行性 | 分布外动作可能被误判为可行 |
| 二元可行性分类足够——动作要么可行要么不可行 | 物理可行性通常是连续的（「摩擦力够不够」是程度问题而非是非问题） |
| RoBERTa 可以只从文本描述学习物理可行性 | 文本描述不包含真实物理参数（当前摩擦系数是多少？） |
| GPT-4 规划器 + RoBERTa 判据的架构不需要进一步隔离 | **C_F 可以理论上被独立部署，但论文并未将其与 LLM 隔离**——GPT-4 和 RoBERTa 在同一软件栈中 |

**对我们的意义**（框架借鉴 + 关键差异）

DDCG 的「可行性判据 C_F + 质量判据 C_Q 分离」框架**在概念层面非常接近我们的思路**——硬件隔离的安全判据层 = 我们的 C_F 等效物。但关键差异：

| 维度 | DDCG C_F | 我们的安全判据 |
|------|---------|--------------|
| 实现 | RoBERTa 神经网络（从训练数据学习可行性） | **显式物理公式**（摩擦方程、稳定性判据） |
| 输入 | 文本描述的动作+状态 | **传感器数据**（IMU、力传感器、深度） |
| 部署 | 与 GPT-4 在同一软件栈中 | **TEE 隔离**（防止被攻陷的 OS/LLM 绕过） |
| 可行性概念 | 从训练数据中学到的「可行性」 | 物理定律决定的「安全性」 |

**局限/盲区**（从我们视角看）

- **C_F 是神经网络，不是形式化保证**：RoBERTa 判断可行性——这本身就可能出错。在分布外场景中，C_F 可能给出错误的可行性判断，而我们无从知晓
- **C_F 训练数据来自仿真**（VirtualHome/ScienceWorld），这些仿真中的「不可行」概念不包含真实物理参数
- **不接入传感器**：C_F 从文本描述推断物理可行性——文本中说「地面是湿的」和传感器测到摩擦系数 0.2 是完全不同的信息源
- **在 LLM 同一软件栈中部署**：没有独立的安全边界——被越狱的 LLM 理论上可以绕过或操纵 C_F
- **未在物理机器人上验证**——仅 VirtualHome 和 ScienceWorld 仿真

### 6. VerifyLLM: LLM-Based Pre-Execution Task Plan Verification for Robots

**出处**：Grigorev, Kovalev, Panov (MIPT/AIRI), IROS 2025  
**全文获取**：⚠️ 仅抽象级（arXiv 摘要页，全文无法直接获取）。以下分析基于摘要信息 + 项目页面。标注「基于摘要分析，待获取全文确认」。

**核心方法**（基于可获取信息）

VerifyLLM 将自然语言指令转换为**线性时序逻辑（LTL）**，然后用 LLM 评估逻辑一致性并识别计划中的潜在缺口。两步流水线：
1. NL → LTL 转换
2. LLM 基于 LTL 规范对动作序列进行系统性分析，评估逻辑一致性和识别缺口

**实验设置**

- 在「不同复杂度的数据集」上测试（具体数据集名称未在摘要中列出）
- 聚焦家庭任务（household tasks）
- IROS 2025 已接收

**关键数据**

⚠️ 摘要中无具体数值。声明在家庭任务上「展示了该模块的广泛适用性」。

**安全假设**（基于方法论推断）

| 假设 | 含义 |
|------|------|
| LTL 规范能充分表达所有安全约束 | 连续物理量（摩擦力、倾角）难以用 LTL 表达 |
| LLM 转换 NL 到 LTL 是正确的 | 转换错误导致验证错误 |
| LLM 能够正确评估 LTL 规范的满足性 | 与「LLM 审查 LLM」相同的问题 |

**对我们的意义**（差异化对照）

VerifyLLM 是 pre-execution verification 范式在机器人领域的**代表性工作**——它证明了「执行前验证」这个 idea 在 2025 年已被 IROS 社区接受。我们的差异化：

| 维度 | VerifyLLM | 我们的方向 |
|------|----------|-----------|
| 验证手段 | LTL 形式化规范 + LLM 逻辑评估 | **物理公式** + **传感器数据** |
| 覆盖的安全属性 | 时序逻辑（动作顺序、前置条件满足性） | **连续物理安全**（摩擦、倾角、负重） |
| 是否接入物理世界 | ❌——LTL 规范是抽象的逻辑公式 | ✅——IMU/力传感器/深度相机 |
| 是否独立于 LLM | ❌——LLM 既生成 LTL 又评估 LTL | ✅——判据是物理公式，不依赖 LLM |

**局限/盲区**（从我们视角看）

- **LTL 只能表达离散的逻辑属性**——「机器人必须在打开烤箱前检查里面是否有易燃物」可以表达，但「地面摩擦系数必须大于 0.3 才能安全搬运 5kg 重物通过 15° 斜坡」在 LTL 中无法自然表达
- **LTL 规范的正确性依赖于转换的准确性**——NL→LTL 转换由 LLM 完成，转换错误导致验证盲区
- 不接入传感器——不知道当前物理环境的真实状态
- 仅验证「逻辑一致性」，不验证「物理可行性」
- ⚠️ 以上局限判断基于方法论特征推断，**需获取全文确认**具体失败案例和作者自述的局限

### 7. SAFER: Safety Aware Task Planning via Large Language Models in Robotics

**出处**：Khan et al. (UMN/Georgia Tech), IROS 2025  
**全文获取**：✅ 完整（ar5iv HTML）

**核心方法**

SAFER 是一个多 LLM + 控制屏障函数（CBF）的安全框架，由四个模块组成：

1. **规划模块**：两个专门的 LLM 协作——**Task Planning LLM**（主要编排器，将高层目标分解为子任务）和 **Safety Planning LLM**（审计生成的序列，提供安全反馈，识别空间冲突/无效动作依赖/遗漏前置条件）。反馈循环：Safety LLM 审计 → 反馈给 Task LLM → 迭代优化计划。

2. **执行模块**：异构机器人 agent，每个有独立的 Robot Execution LLM。

3. **LLM-as-a-Judge**：专用 LLM 根据 **15 个风险标准**评估任务计划（具体 15 项标准在论文中未逐一列出，仅提及「如动作依赖、空间约束、人机交互风险」等示例）。产生结构化的安全报告，而非二元通过/失败。

4. **CBF 集成**（最关键的安全机制）：安全在控制层通过 QP 求解器强制执行——$$\min_u \frac{1}{2}\|u - u^{nom}\|^2$$ 受 CBF 不等式约束。两类约束：关节安全（位置/速度/力矩限制）和操作空间安全（避障、工作空间限制、奇异性避免、机器人间碰撞）。

**实验设置**

| 维度 | 内容 |
|------|------|
| 仿真基准 | COHERENT（40 任务，5 场景，mono/dual/trio 类型） |
| 真实硬件 | 两台 Kuka IIWA LBR 14 机械臂 + Clearpath Ridgeback 移动底座，Vicon 追踪 |
| LLM | GPT-4o、DeepSeek-r1 |
| 安全机制 | CBF 在关节空间和操作空间强制执行 |

**关键数据**

| 指标 | 数值 |
|------|------|
| 安全违规减少（SAFER + GPT-4o vs 无安全 GPT-4o） | **47%** |
| 安全违规减少（SAFER + DeepSeek-r1 vs 无安全 GPT-4o） | **77.5%** |
| 计算开销 | 「仅最小的增加」（每步两次 API 调用） |

**四个关键实证观察**（论文原文）：
1. 更强的推理 → 更好的安全：DeepSeek-r1 产生更少违规——因为它「能生成更结构化、更有远见的计划」
2. LLM 作为安全评判者比作为答案验证者表现出更少的自偏——安全评估「可能涉及更明确的基于规则的检查，需要客观性」
3. 多 LLM 框架可以平衡效率和安全性
4. 没有明确安全指令时，LLM 自然优先速度——「经常遗漏重要的安全细节」

**⚠️ 关键问题：Safety LLM 本身是否会被越狱？**

**论文不讨论此问题。** 在全文任何地方都没有涉及对抗攻击、提示注入或 Safety LLM 对越狱的鲁棒性。这是 SAFER 安全模型中最根本的未审视假设——整个安全架构的有效性取决于 Safety LLM 本身没有被攻陷。

**安全假设**（显式 + 隐式）

| 假设 | 风险 |
|------|------|
| Safety LLM 的反馈是可信和正确的 | **最大盲区**——被越狱的 Safety LLM 可能批准危险计划 |
| CBF 约束能充分捕获所有安全需求 | 仅覆盖可达性/碰撞/关节限制，不覆盖非运动学安全（如物体是否太重） |
| 障碍物几何和位置是先验已知的 | 需要预标定的桌子位置、Vicon 追踪头盔 |
| CBF 对控制有最终决定权 | CBF 在控制层执行——但控制层假设来自规划层的指令是善意的 |
| 真实传感器数据仅到达 CBF（控制层） | Safety LLM 不直接摄取传感器数据 |

**对我们的意义**（关键差异化对照）

SAFER 是目前**最完整的 LLM 规划安全框架**——但它恰恰展示了「多 LLM 审查 LLM」路线的根本局限：

| 维度 | SAFER | 我们的方向 |
|------|-------|-----------|
| 安全评估者 | Safety LLM（另一个 LLM） | **物理公式判据**（非 LLM） |
| 传感器接入 | 仅 CBF 控制层（不达 LLM） | **判据层直接接入传感器** |
| 隔离 | ❌——所有 LLM 在同一软件栈 | ✅——判据在 TEE 隔离环境 |
| 对抗鲁棒性 | 未评估（Safety LLM 可被越狱） | 判据不是 LLM，语义越狱不适用 |

**局限/盲区**（从我们视角看）

- **「LLM 审查 LLM」的架构假设未经验证**：Safety LLM 和 Task LLM 共享相同的根本局限——它们都是 LLM，都可能被越狱
- **真实的物理安全在执行时由 CBF 保证，而非 LLM**——SAFER 的实际安全来自数学确定性的 QP 求解器 + CBF 约束，LLM 只提供高层语义判断。这暗示了一个重要结论：**在物理安全关键路径上，数学确定性的方法优于 LLM**
- CBF 覆盖的安全维度有限——运动学约束（位置/速度/力矩/避障），不包括物理前提（摩擦、重量、稳定性）
- 需要外部追踪系统（Vicon），限制了实际部署

### 8. ILION: Deterministic Geometric Pre-Execution Verification

**出处**：Zenodo/tech report, 2025.05（v33）；patent pending (Romania, 2026.02)  
**全文获取**：⚠️ 基于 Zenodo 记录页摘要 + HuggingFace 论文摘要 + 搜索信息。非同行评审。部分标注「待验证」。

**核心方法**（基于可获取信息）

ILION（Intelligent Logic Identity Operations Network）是一个**确定性几何预执行验证层**，评估 AI 生成的执行决策。与概率性护栏系统（依赖二次 LLM 推理）不同，ILION 使用**固定参考向量**和**校准阈值**强制执行确定性几何约束。

五组件级联架构：
1. **TII（Transient Identity Imprint）**：跨会话身份连续性，无需持久记忆
2. **SVRF（Semantic Vector Reference Frame）**：语义垂直共振场——基础对齐层
3. **IDC（Identity Drift Control）**：身份漂移控制（详细机制未公开）
4. **IRS/IIRL（Inter-Instance Resonance Layer）**：跨并行实例的实时语义对齐
5. **CVL（Consensus Veto Layer）**：不可协商的公理护栏，单个公理违规即可阻止共识

**关键数据**（⚠️ 来源：Zenodo + HuggingFace 摘要，需独立验证）

| 指标 | 数值 |
|------|------|
| 决策确定性 | **100%**（1,000 次重复评估零方差） |
| 全级联延迟（中位数） | **6.7 ms** |
| 门控仅延迟 | **< 2 μs** |
| 异常检测 ROC-AUC | 0.79（独立几何层）→ 0.91（可选学习几何组合） |
| ILION-Bench v2 | 380 测试场景，8 攻击类别，39% 高难度对抗案例 |
| F1 | **0.8515** |
| 精确率 | **91.0%** |
| 假阳性率 | **7.9%** |
| 平均延迟 | **143 μs** |

与传统护栏对比：
- Lakera Guard: F1 = 0.8087
- OpenAI Moderation API: F1 = 0.1188
- Llama Guard 3: F1 = 0.0105

**几何验证 vs 物理验证的边界**

⚠️ 这是最关键的概念区分，但 Zenodo 摘要未做此对比（以下基于方法论特征的推断）：

ILION 的「几何」操作在**嵌入/向量空间**中进行——它检查 AI 输出是否落在预定义的向量边界内。这是一种**语义几何**：验证 AI 的决策向量是否与安全参考向量对齐。

而「物理验证」需要检查真实世界的物理量：摩擦力、倾角、重量、惯性。这些不在嵌入空间中——它们在牛顿力学空间中。

| 维度 | ILION 几何验证 | 物理验证 |
|------|--------------|---------|
| 操作空间 | 嵌入空间（向量） | 物理空间（牛顿力学） |
| 参考框架 | 固定参考向量 | 传感器数据（IMU、力传感器） |
| 阈值来源 | 校准阈值 | 物理定律（摩擦方程、稳定性判据） |
| 验证目标 | 决策语义是否在安全边界内 | 动作在真实物理环境中是否安全 |

**安全假设**

| 假设 | 风险 |
|------|------|
| 安全可以在嵌入空间中通过几何约束完全定义 | **最大局限**——物理安全性不是嵌入空间的几何属性 |
| 语义向量对齐 = 物理安全 | 「把重物搬过去」在向量空间中语义正确 → 不等于地面摩擦系数满足安全要求 |
| 确定性 = 正确性 | 100% 确定性保证了可重复性，但不保证判据本身正确 |

**对我们的意义**（架构参考 + 关键反面论证）

ILION 的价值在两方面：
1. **正面**：它证明了确定性预执行验证的技术可行性——6.7ms 延迟、100% 确定性、不需要 LLM。这支撑了「非 AI 的安全判据层」的技术可行性。
2. **反面**：它精确地展示了为什么**几何验证 ≠ 物理安全验证**。ILION 在嵌入空间中操作，完全无法感知物理参数——这正好是我们想填补的空白。

**局限/盲区**（从我们视角看）

- **未经过同行评审**（Zenodo tech report, patent pending）——可信度待验证。声称的 100% 确定性需要独立复现
- **嵌入空间的几何约束 ≠ 物理安全**：一个动作在语义空间中看起来安全（「把箱子搬到架子上」），但在物理空间中可能危险（地面湿滑、箱子超重）
- **物理参数（摩擦、负载、稳定性）完全不出现**——ILION 验证的是 AI 输出的语义合规性，不是物理可行性
- **专利状态**——可能影响学术使用的自由度
- ⚠️ 以上局限分析基于方法论特征推断，**需获取完整技术 PDF 确认**

## Part D：关键发现总结

### 发现 1：Pre-execution verification 是 2025 年的活跃前沿

三篇 IROS 2025 论文（VerifyLLM, SAFER, + 我们发现的 SAFEL/EMNLP 2025）以及 NeurIPS 2025 的 DDCG，证明了「执行前验证」这个范式已被顶会社区接受。**这强化而非削弱我们的定位**——我们在正确的时间切入正确的范式，提供的是该范式中缺失的物理接地变体。

### 发现 2：所有现有系统共享一个根本盲区

7 个防御系统中的每一个（ConceptAgent, DDCG, VerifyLLM, SAFER, ILION, 加上 Causal Reasoner 和 ContextMatters）都在**不接入真实物理传感器数据**的情况下做安全判断。它们从文本、嵌入向量、场景图、LTL 公式或仿真训练数据中推断安全——没有一个从 IMU/力传感器/深度相机读取摩擦系数、倾角或负重。

**这是我们的核心差异化空间。**

### 发现 3：ConceptAgent 是方法论上最接近的竞争者——但差异清晰

ConceptAgent 和我们都做「规划后-执行前验证」。但它的验证规范（前置条件）由 LLM 生成，验证内容限于 17 个布尔谓词，状态来自视觉场景图。我们的验证规范来自物理公式，验证内容是连续物理量，状态来自物理传感器。不同点在每一步上都是清晰的。

### 发现 4：SAFER 的 CBF 组件暗示了正确方向

SAFER 的安全关键路径实际上不在 LLM 中——它在 CBF+QP 求解器中（数学确定性的）。论文数据也支撑这一点：DeepSeek-r1 推理更强所以违规更少，但真正的安全保证来自 QP 求解器中的数学约束。**这暗示了我们的判断是正确的：物理安全的最终保证应该来自数学确定性方法，而非 LLM。**

### 发现 5：ILION 的「几何验证」是我们方向的反面教材

ILION 恰好展示了我们**不做**的事情——在嵌入空间中用几何约束做语义合规检查。它的 100% 确定性是一个 attractive property，但它的验证对象（语义对齐）和我们的验证对象（物理安全）是正交的。这两者可以互补：ILION 做「这个动作在语义上说得通吗？」，我们做「这个动作在当前物理环境中安全吗？」

### E.1 已确认的关键细节

#### Q1: C_F 的训练数据具体是什么？

DDCG 使用**三类合成数据**（§3.3，p.4-5），全部基于 VirtualHome 环境生成：

| 数据类型 | 构成方式 | 评分 | 用途 |
|---------|---------|:--:|------|
| **Expert Data** | VirtualHome 的 ground-truth 最优动作序列 | 10 | C_F 和 C_Q 的黄金标准 |
| **Hard Negative Samples** | 对 expert actions 施加**基于规则的扰动**——违反前置条件（如「在抓住物体之前尝试切片」）或破坏动作语法 | <3 | **专门为 C_F 设计**——教 C_F 识别物理/逻辑违规 |
| **Suboptimal Data** | 使用**微调后的 FLAN-T5 + beam search** 生成大量候选动作，通过**与 expert action 的语义相似度**赋予 3-9 分 | 3-9 | C_Q 的回归训练 + C_F 的多样化正例 |

**原文关键引用**（p.5）：
> "Hard Negative Samples...are generated by applying rule-based perturbations to expert actions, creating actions that are explicitly infeasible. The perturbations include violating preconditions (e.g., attempting to `slice` an object before it is held) or breaking action syntax."

**关键发现**：「不可行」的 ground truth label **不来自仿真引擎的错误码或人工标注**，而是来自**基于规则的程序化生成**——攻击者手动定义哪些是「前置条件违反」，然后用程序自动生成对应的负样本。这意味着 C_F 只能学到**规则设计者事先想到的违规模式**。

#### Q2: C_F 的架构细节

（§4.1 Table 1, p.6）

| 参数 | 值 |
|------|-----|
| 模型架构 | **RoBERTa-base** |
| 任务类型 | 二分类（feasible=1 / infeasible=0） |
| 最大序列长度 | **256 tokens** |
| 学习率 | 1e-5 |
| 优化器 | AdamW (weight_decay=0.01, warmup_ratio=0.1) |
| Batch size | 32 |
| 训练轮数 | 5 |
| 损失函数 | Binary Cross-Entropy |

**输入格式**（从方法描述推断，原文未给出精确的 token 序列格式）：C_F 接收「当前状态 s + 候选动作 a」的文本描述。状态 s 来自 VirtualHome 的文本环境描述（如 "the fridge is closed, the chicken is inside the fridge"），动作 a 是文本形式的动作指令（如 "grab('chicken')"）。由于最大序列长度仅 256 tokens，输入必须高度精简。

**关键发现**：输入中**不包含任何数值物理参数**。所有信息都是文本——VirtualHome 仿真中的对象名称、状态（开/关/在里面）、动作名称。摩擦系数、重量、倾角等概念在 C_F 的训练和推理中**完全不存在**。

#### Q3: C_F 的失败模式

**论文未报告 C_F 的 false positive / false negative 分析**。全文（含附录）中没有独立评估 C_F 分类性能的表格或指标。主要的评估指标是整体系统的 Executability（Exec）和 Success Rate（SR），而非 C_F 的单独表现。

消融实验（§4.3, Table 3, p.7）提供了间接证据：

| 设置 | Full DDCG Exec | w/o C_F Exec | C_F 贡献 |
|------|:--:|:--:|:--:|
| In-Distribution | 95.0% | 89.4% | +5.6% |
| Novel Scenes | 75.6% | 74.2% | +1.4% |
| Novel Tasks | 83.3% | 78.9% | +4.4% |

C_F 在分布外场景（Novel Scenes）的贡献明显下降（仅 +1.4%），暗示 C_F 在未见过场景中的可行性判断能力有限。但论文未对此做进一步分析。

**原文未讨论的问题**：C_F 的 false positive（判为可行但实际不可行）可能导致物理危险动作被执行；C_F 的 false negative（判为不可行但实际可行）可能导致过度保守的拦截。这两种错误的安全后果完全不同，但论文未做区分。

#### Q4: 与 LLM 的部署关系

**论文完全未讨论 C_F 与 GPT-4 的进程隔离、安全边界或对抗鲁棒性。**

Algorithm 1（p.5）显示了在线规划流程：
```
1. LLM Planner 提出候选动作 a
2. C_F(s, a) 做可行性检查 → 不可行则反馈给 LLM
3. C_Q(s, a) 做质量评估 → 低于阈值 τ 则反馈给 LLM
4. 通过两道门槛后在环境中执行
```

这个流程中，C_F 和 GPT-4 在**同一控制流**中运行。论文未指定它们是否在不同进程中，也未讨论如果 LLM（GPT-4）被攻陷（如通过 Blindfold 越狱），C_F 是否还能独立运作。

**从架构推断**：DDCG 的 C_F 和 GPT-4 极可能在同一 Python 运行时中通过 API 调用交互（GPT-4 通过 OpenAI API，C_F 是本地 RoBERTa 模型）。这意味着被越狱的 LLM 理论上可以绕过或操纵 C_F——例如，越狱的 LLM 可以选择不调用 C_F 检查，或者忽略 C_F 的否决并直接输出动作。

**这是 DDCG 安全模型中最根本的盲区**：安全判据（C_F）和被它约束的规划器（GPT-4）共享同一信任边界。

#### Q5: CMDP 形式化的具体约束

（§3.1, p.3-4）

DDCG 将具身规划问题形式化为**受约束马尔可夫决策过程（CMDP）**，定义如下：

- **状态空间 S**：环境的文本描述（"textual descriptions of the environment"）
- **动作空间 A**：可能动作的文本描述（"textual descriptions of possible actions"）
- **不可行动作的代价函数 C(s,a)**：对于任何不可行动作 = **无穷大**；对于可行动作 = 0
- **代价阈值 d = 0**：零容忍——不允许任何不可行动作
- **安全动作集 A_safe(s)** = `{a ∈ A | C_F(s,a) = 1}`——完全由 C_F 的预测定义，**没有独立的规则集**

**原文关键引用**（p.3）：
> "We assume that any infeasible action (violating physical or logical rules) will lead to catastrophic failure. Therefore, the cost function is infinite for any infeasible action and zero otherwise."

**关键发现**：A_safe 的定义**完全依赖于 C_F 的神经网络输出**。没有独立的、基于物理公式或形式化规则的备用安全定义。如果 C_F 出错（false positive），不可行动作就进入了 A_safe——在 CMDP 框架中，这被视为「灾难性失败」，但没有任何机制可以检测或纠正这种失败。

#### Q6: 长时域场景的具体数据

DDCG 仅在 **VirtualHome** 上评估（§4.1, p.5-6）。**ScienceWorld 不在本文中**——此前搜索摘要中的 ScienceWorld 数据系错误汇总。

VirtualHome 被描述为「需要长时域规划的挑战性 3D 仿真」（p.6），但论文未报告具体的任务长度分布、平均步骤数或长时域 vs 短时域的细分结果。三个评估设置（In-Distribution / Novel Scenes / Novel Tasks）的主要结果：

| 设置 | Exec (%) | SR (%) |
|------|:--:|:--:|
| In-Distribution | 95.0 | 94.1 |
| Novel Scenes | 75.6 | 73.6 |
| Novel Tasks | 83.3 | 81.8 |

**关于 C_F 在长时域是否会累积错误**：论文完全未讨论此问题。C_F 在每个步骤独立判断，没有跨步骤一致性检查或累积误差监控。

#### Q7: 论文自述的局限

**论文的 Limitations 部分（Appendix A.2, p.10）仅有两句话**：

> "The performance of our DDCG framework is dependent on the quality of the synthetically generated data and introduces computational overhead, while its generalization to physical robotics requires further validation."

这极其简略。论文未提及的局限包括：

| 接入传感器？ | ❌ | **保持不变**——全文确认：C_F 输入为文本描述（max 256 tokens），无传感器数据 |

**新增关键发现**（强化差异化论证）：

1. **C_F 的「不可行」定义完全由人工规则决定**（你事先告诉模型什么违规模式算「不可行」），这意味着 C_F 无法检测规则设计者未曾预见的危险场景。
2. **CMDP 框架中的 d=0 假设**（零容忍不可行动作）在真实物理世界中不成立——并非所有不可行动作都是「灾难性」的。这导致 DDCG 的安全模型过于简单（二元可行/不可行），而真实物理安全需要更精细的评估（摩擦系数够不够？稳定性裕度多大？）。
3. **Limitations 仅两句话**——论文未对安全关键问题（对抗鲁棒性、分布外泛化、累积误差）做任何讨论。这强化了它在安全架构设计上不成熟的判断。
